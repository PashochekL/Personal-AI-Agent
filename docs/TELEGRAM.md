# Telegram-бот Дамира

Один бот обслуживает от 1 до 32 разрешённых Telegram-аккаунтов в личных чатах.
У каждого ID отдельный backend с ключом, история, память, настройки модели
и навыка, рабочий Docker-том и shell-песочница. Agent Loop остаётся в Core.
HTTP-транспорт CLI и Telegram расположен в `interfaces/http/`.
Новых NuGet-зависимостей и изменений shared нет.

## Подключение и список аккаунтов

1. Создай бота через официального [@BotFather](https://t.me/BotFather), `/newbot`.
   Сохрани токен локально. Не отправляй его в чат разработки или Git.
2. Подготовь числовые Telegram ID разрешённых людей: `message.from.id`,
   не @username и не ID бота.
3. Запусти Docker Desktop и выполни `damir login`, если вход ещё не сделан.
4. Выполни `damir telegram`. В репозитории: `.\damir.cmd telegram` на Windows
   или `./damir telegram` на macOS/Linux.
5. Введи токен скрыто, затем ID через запятую: `123456789,987654321`.
6. Каждый разрешённый пользователь открывает бота и отправляет `/start`.

Список сохраняется в `.uv-cache/telegram-users-{bot_id}.txt`. На Windows
после первого ввода токен также сохраняется в `.uv-cache/telegram-token.dpapi`,
зашифрованный Windows DPAPI для текущего пользователя и компьютера. Обычный
повторный запуск `.\damir.cmd telegram` использует эти данные без вопросов.
При обновлении уже настроенного launcher токен потребуется ввести ещё один раз;
прежний сохранённый список ID подхватится автоматически.

На macOS первый введённый токен сохраняется в системной «Связке ключей» через
`git credential-osxkeychain`, входящий в Git для macOS. В файлы проекта токен
не записывается. Повторный `./damir telegram` использует токен и список ID
без вопросов. macOS может запросить разрешение на доступ к «Связке ключей».
Запись привязана к пути репозитория Дамира и системному пользователю:
после переноса репозитория или на другом компьютере токен вводится заново.

Для смены токена или списка останови бота и выполни:

- Windows: `.\damir.cmd telegram -ConfigureTelegram`.
- macOS: `./damir telegram --configure`.

Введи токен и новый полный список ID. Enter в списке оставляет сохранённые ID
для этого бота. Эти команды позволяют заменить повреждённый или устаревший
токен. Локальные настройки в `.uv-cache/` исключены из Git и Docker build context.
На Linux токен по-прежнему вводится при запуске или передаётся через окружение;
сохранённые ID используются автоматически, для их изменения есть `--configure`.
Изменение списка из Telegram пока не реализовано.

Для автоматического запуска задай `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_ALLOWED_USER_IDS=123456789,987654321`. Список имеет приоритет
над старой `TELEGRAM_ALLOWED_USER_ID`, поддерживаемой для одного ID.
Повторы убираются. Пустые, отрицательные, некорректные ID и список длиннее 32
отклоняются до Docker. Без списка доступа бот не работает. Переменные окружения
имеют приоритет над сохранёнными данными; токен из окружения автоматически
не сохраняется. Режим настройки (`-ConfigureTelegram` на Windows, `--configure`
на macOS/Linux) явно запрашивает новые данные, даже если переменные заданы.
`.env.example` — образец; .NET-приложение само его не загружает.

На Windows launcher хранит только зашифрованный токен, на macOS — запись
в «Связке ключей»; на Linux автосохранения токена нет.
Docker получает токен через окружение контейнера бота.
Ключи аккаунтов сохраняются в игнорируемой Git папке
`.uv-cache/telegram-keys/`. Временный манифест с ключами монтируется только
в получатель Telegram и удаляется после остановки.

Публичный сервер не нужен: используется официальный
[Bot API](https://core.telegram.org/bots/api), `getUpdates`.
Непустой webhook вызывает отказ запуска и автоматически не удаляется.
Для одного бота запускается один получатель. Компьютер и процесс должны работать.
Группы, каналы, посторонние ID и сообщения ботов не передаются агенту.

## Разделение данных

Получатель выбирает backend по фактическому `message.from.id` после проверки
личного чата. Пользователь и модель не могут передать другой owner, проект,
ключ или workspace. При запуске защищённый `/identity` проверяет backend
на соответствие аккаунту. Общий backend или ключ для двух ID запрещён.

Owner: `telegram:{bot_id}:{user_id}`. Проект определяется хешем исходной пары
`DAMIR_MEMORY_OWNER` и `DAMIR_MEMORY_PROJECT`; исходный проект launcher
вычисляет как при обычном запуске. Сохранённое состояние бота привязано к этой
паре: смена исходного проекта без отдельного каталога состояния отклоняется.
Новая сессия внутри аккаунта сохраняет его долговременную память.

Backend и shell видят только свой постоянный том `/workspace` и свой IPC-том.
Shell работает без сети; backend не публикует порты на хост.
Папка проекта с компьютера, файлы CLI и общий GitHub MCP с токеном владельца
не подключаются. Начальный workspace пустой; навыки и файлы хоста не копируются.
Обычный CLI работает в своём окружении и не открывает диалоги Telegram.

PostgreSQL, Redis, шлюз моделей и сервис поиска используются совместно.
История, задачи и память фильтруются по owner/project; backend связывает
bearer-ключ с одной парой. Администратор Docker/БД и получатель Telegram имеют
технический доступ к данным. Это разделение пользователей на доверенном хосте.
Отдельные БД и лимиты стоимости на пользователя не реализованы.
Число контейнеров и потребление ресурсов растут со списком ID.

Удаление ID прекращает приём и доставку ему после перезапуска. Его файлы,
история, память, ключ и незавершённые квитанции сохраняются. Принятые задачи
могли уже выполнить действия; удаление ID их не откатывает.
Повторное добавление того же ID в том же проекте восстанавливает его состояние.
Автоматического удаления пользовательских данных нет.

## Команды

| Команда | Действие в своём аккаунте |
| --- | --- |
| `/start`, `/help` | Справка |
| `/session [ID]` | Текущий диалог или открытие своей сессии |
| `/new` | Новая сессия |
| `/status [ID]` | Состояние и результат задачи текущей сессии |
| `/cancel [ID]` | Запрос отмены последней или указанной задачи |
| `/models [номер]` | Каталог или выбор модели |
| `/skill [имя]`, `/skill 0` | Выбор навыка на один ход, отмена |
| `/tokens` | Сохранённый расход текущей сессии |
| `/context`, `/compress` | Оценка и сжатие через очередь backend |

Обычный текст создаёт задачу. Фото, голос, загрузка файлов, кнопки и изменение
сообщений пока не поддержаны. Ответы идут обычным текстом, длинные делятся
на части с сохранением Unicode. Приём и доставка независимы: `/cancel` доступна
во время генерации. Отмена кооперативная, действия инструментов не откатывает.

## Восстановление и переход со старого режима

Перед подтверждением обновления сохраняется квитанция с update_id, сессией,
сообщением, настройками и постоянным Idempotency-Key. Повтор после потери
HTTP-ответа возвращает ту же задачу. Текст запроса удаляется из транспортного
состояния после подготовки ответа; история остаётся на backend.

Том `damir_telegram_state` хранит общую точку `{bot_id}.router.json` и отдельное
состояние `{bot_id}-user-{user_id}.json` на ID. В нём временно находятся тексты
запросов и ответов; токен не записывается. Сохранение атомарное, блокировки
исключают второй локальный получатель. Другой компьютер может вызвать 409 Telegram.

Лимиты на аккаунт: 20 незавершённых задач и 100 квитанций. При 100 квитанциях
новые сообщения этого аккаунта пропускаются с записью в журнал, чтобы остальные
продолжали работать. Ошибка его backend или блокировка бота одним пользователем
не останавливает остальных после инициализации. Первоначальный запуск требует
доступности всех backend. Сетевые ошибки повторяются; 429 учитывает `retry_after`.
При потере подтверждения `sendMessage` последняя часть может прийти дважды:
Telegram не предоставляет для неё ключ повтора. Агент повторно не запускается.

Из старого `{bot_id}.json` переносится только позиция обновлений. Прежние
общие сессии, память и файлы новым аккаунтам не назначаются. Если остались
старые ответы, запуск предложит сначала выполнить `damir telegram-drain`
с прежним единственным ID и тем же исходным проектом. Этот режим завершает
старые отправки через прежний backend, не принимает новых сообщений
и завершается после очистки квитанций. Затем запусти `damir telegram` со списком.

Остановка launcher останавливает созданные им контейнеры и удаляет временные
IPC-тома и манифест. Рабочие тома аккаунтов, БД и состояние остаются.
Удаление состояния и потеря диска не покрываются гарантией восстановления.

Без launcher требуется `DAMIR_TELEGRAM_BACKENDS_FILE`: JSON-массив с полями
`user_id`, `url`, `api_key`, `owner_id`, `project_id`, по записи на разрешённый ID.
Его готовит доверенный администратор вместе с отдельными backend и workspace.
Общий backend по умолчанию не используется. Также нужны токен, список ID,
исходные owner/project; необязательны `DAMIR_SESSION_ID` и
`DAMIR_TELEGRAM_STATE_DIR` (по умолчанию `.uv-cache/telegram-state`).

## Проверки

Если после обновления появляется прежнее приглашение «Твой числовой Telegram ID»
и сообщение об общем сервере, заверши этот запуск и снова выполни
`.\damir.cmd telegram` из текущего репозитория. Новый launcher спрашивает список
ID через запятую и создаёт файл изолированных backend. Запуск без этого файла
отклоняется с подсказкой; Compose не создаёт вместо него пустой каталог.
Предупреждение о ранее созданном томе embeddings само по себе не означает
ошибку Telegram. Не удаляй тома памяти или состояния для исправления запуска.

- `dotnet run --project tests/TelegramTests/TelegramTests.csproj`: доступ,
  маршрутизация, повторы, команды, миграция и добавление/удаление ID.
- `pwsh -NoProfile -File tests/BackendTests/run-integration.ps1`: настоящие
  PostgreSQL, Redis, Core, история, память и файловые инструменты двух аккаунтов.
- `pwsh -NoProfile -File tests/TelegramTests/run-isolation-smoke.ps1`: отдельные
  Docker workspace/IPC, shell без сети и выполнение команд через Core.
- `tests/windows-launcher-check.ps1` и `tests/LaunchTests/telegram.sh`: запуск.
- `tests/LaunchTests/telegram-settings.sh`: macOS-настройки с поддельными
  «Связкой ключей» и Docker: сохранение, повторный запуск без вопросов, смена
  токена/ID, приоритет окружения, ошибки хранилища и разделение копий проекта.
  Настоящий доступ к «Связке ключей» нужно проверить отдельно на Mac.

Telegram и модель в проверках синтетические: живым пользователям сообщения
не отправляются, платных запросов нет.
