# Дамир: продолжить диалог в Telegram

## Обычный сценарий

Можно сразу запустить `damir telegram` в папке проекта: он открывает локальную
консоль и автоматически показывает ссылку на собственного бота. Внешний сервер
не нужен. У каждого пользователя свой бот и один раз сохранённый токен.
В уже открытой консоли тот же переход выполняет `/tg`.

1. Запусти Docker Desktop. Открой терминал в папке своего проекта и запусти `damir` (в репозитории Windows — `.\damir.cmd`).
2. Поговори с Дамиром, затем введи `/tg`.
3. Открой показанную ссылку и нажми «Начать» в Telegram. Числовые ID вводить не нужно.
4. Бот покажет последние 12 сообщений диалога; длинные сообщения в этом обзоре сокращаются. Полная история остаётся в общей БД и доступна Core. Можно продолжать разговор и просить файлы: «Пришли сюда файл report.pdf из проекта».
5. Для возврата нажми «На компьютер» в боте или введи `/console` в открытой консоли. В пределах этого же запуска снова писать в Telegram можно через «Продолжить здесь», без новой ссылки. После перезапуска или смены папки сначала открой свежую ссылку.

Пока диалог открыт в Telegram, backend отклоняет новые сообщения в этот же диалог из консоли. Пока он открыт в консоли, Telegram не принимает новые запросы агента. Переключение возможно после завершения или отмены активной задачи. История, память, рабочая папка, выбранная модель и навык следующего хода передаются через тот же backend. Собственного Agent Loop в Telegram нет.

В боте доступны кнопки «Продолжить здесь», «На компьютер», «Остановить», «Команды», «Помощь». «Продолжить здесь» возвращает управление текущим подтверждённым диалогом в Telegram и показывает последние сообщения. Пока Дамир отвечает в консоли, переключение отклоняется: дождись завершения ответа и нажми кнопку снова. Закрепи чат в Telegram, чтобы быстро его находить.

## Меню команд

Кнопка «Команды» открывает действия без ввода ID:

| Кнопка | Действие |
| --- | --- |
| Сжать контекст | Ручное сжатие через Core; исходная история сохраняется |
| Заполнение контекста | Оценка используемого контекста выбранной модели |
| Расход токенов | Сохранённый расход этого диалога |
| Состояние ответа | Очередь, выполнение или результат последнего запроса |
| Выбрать модель | Кнопки из каталога chat-моделей backend |
| Выбрать навык | Кнопки навыков текущего проекта; выбор на одно обычное сообщение |
| История диалога | Последние сообщения текущей сессии |
| Текущий проект | Название рабочей папки, интерфейс, модель и выбранный навык |
| Назад | Возврат к разговору и основным кнопкам |

Доступны также `/commands`, `/compress`, `/context`, `/tokens`, `/status`,
`/models`, `/skill`. Сжатие и оценка идут через общую очередь, не записываются
в историю LLM как сообщения и не расходуют выбранный на следующий ход навык.
Во время текущего ответа новое действие не запускается. В меню Telegram
зарегистрированы запуск, помощь и «Меню команд».

## Смена папки и сохранение истории

Папка запуска определяет workspace и проект в БД. Обычный запуск в другой папке
открывает отдельную сессию; возвращение по тому же пути открывает прежнюю сессию
со всей сохранённой историей. Обзор в Telegram ограничен 12 сообщениями;
полный контекст остаётся у Дамира. Переименование или перенос папки меняет проект.

Telegram показывает один чат с ботом: ссылки не создают отдельные Telegram-чаты
для папок. При открытии свежей ссылки бот указывает название активной папки.

| Сценарий | Результат |
| --- | --- |
| Запущен A, ссылка A открыта | Telegram работает с файлами и историей A |
| A закрыт, запущен B, свежая ссылка не открыта | Старые сообщения и кнопки не выполняются в B; бот просит открыть свежую ссылку, если получатель уже запущен |
| Открыта свежая ссылка B | Этот чат управляет B; история A не добавляется в контекст B |
| Во время запуска B открыта старая ссылка A | Она не переключает проект; бот сообщает, что ссылка устарела |
| B закрыт, снова запущен A и открыта свежая ссылка | Восстанавливается прежний диалог A и его история |

Новый запуск всегда требует подтверждения свежей ссылкой, даже если проект
когда-то оставили в Telegram-режиме. Одновременные получатели одного токена
не допускаются. Если B открыт только обычной консолью без `/tg`, Telegram-
получатель не запущен и сообщений не выполняет.

В персональном режиме разрешён один привязанный Telegram-аккаунт. Посторонний
человек не получает доступ к файлам и переписке. Разные люди могут независимо
работать со своими локальными Дамирами и собственными ботами. Административный
режим нескольких изолированных пользователей описан ниже.

Оставь компьютер и окно Дамира включёнными. При закрытии консоли launcher останавливает персональный backend и Telegram. Это продолжение работы твоего компьютера; отдельного облачного Дамира здесь нет.

## Токен нужен один раз

Для личного бота требуется токен от официального [@BotFather](https://t.me/BotFather). При первом `/tg` без настроенного токена launcher предложит создать бота, скрыто ввести токен и автоматически вернёт в выбранный диалог с новой ссылкой. Модель и выбранный навык сохраняются на время этого перезапуска. Telegram ID бот получает из реального личного сообщения после открытия ссылки и сохраняет в PostgreSQL.

- Windows: `%LOCALAPPDATA%\Damir\telegram-token.dpapi`, шифрование DPAPI для текущего пользователя и компьютера. Токен общий для копий Дамира этого пользователя, сохраняется вне репозитория и используется из любой рабочей папки. Прежний `.uv-cache/telegram-token.dpapi` автоматически переносится после успешной расшифровки.
- macOS: существующая запись в системной «Связке ключей» через `git credential-osxkeychain`.
- Linux: системный Secret Service через `secret-tool`, если доступен. Без него токен остаётся только до закрытия launcher и на следующем запуске вводится снова.

Уже сохранённый токен подхватывается обычным `damir` и `damir telegram`. `TELEGRAM_BOT_TOKEN` из окружения имеет приоритет и автоматически не сохраняется. Смена токена: `damir telegram -ConfigureTelegram` на Windows, `damir telegram --configure` на macOS/Linux. Общего токена разработчиков в коде нет: новый пользователь подключает своего бота один раз. Для одного бота одновременно допускается один получатель; останови старый отдельный Telegram перед использованием `/tg`.

Используется официальный [механизм deep links Telegram](https://core.telegram.org/bots/features#deep-linking). Ссылка содержит случайный одноразовый код, действующий 10 минут; в БД сохраняется только его SHA-256. Новая ссылка заменяет предыдущую. После привязки свежие ссылки принимаются только от прежнего Telegram-аккаунта; чужому человеку нельзя передать доступ пересылкой ссылки. До первой привязки не пересылай ссылку: её обладатель может привязать аккаунт. Переход в группах, сообщения ботов и чужие запросы не открывают историю.

## Рабочая папка и файлы

Launcher подключает именно папку, из которой запущен `damir`, в том числе при запуске из репозитория. Запуск из домашней папки или корня диска отклоняется до Docker. Не выбирай слишком широкую папку с личными данными. Backend и shell получают эту папку; остальные файлы компьютера автоматически не подключаются. Имена сессии и проекта по умолчанию вычисляются по пути папки.

`filesystem.send_to_telegram` — инструмент, доступный Core. Его префикс включает стандартную проверку применимых `AGENTS.md` перед файловой операцией. Он принимает относительный путь, запрещает выход через `..`, абсолютные пути и символические ссылки, читает файл до 20 МиБ и сохраняет снимок в очередь PostgreSQL. Отправка возможна только в привязанный Telegram-диалог, которому передано управление. До трёх файлов могут ожидать отправки для одной сессии. Получатель использует [sendDocument](https://core.telegram.org/bots/api#senddocument) и удаляет файл из очереди после подтверждения Telegram. Отправка выполняется после завершения ответа агента. Входящие вложения и голосовые сообщения пока не поддерживаются.

## Надёжность и ограничения

Привязка, выбранный диалог, позиция обновлений, принятая задача и позиция доставки ответа сохраняются в БД. Потеря квитанции отправки восстанавливается с тем же ключом повтора; агент повторно не запускается. При неопределённом результате `sendMessage` или `sendDocument` возможен повтор последней части или файла: Telegram не предоставляет ключ повтора для этих методов.

Аренда получателя обновляется запросами к backend и истекает через 60 секунд после аварии; параллельная консоль не может забрать активного бота. Один бот последовательно работает с разными проектами того же локального владельца; одновременно нужен отдельный бот на проект. После аварийного завершения незавершённый ответ остаётся в прежней сессии: сначала восстанови этот диалог, затем переключай проект. Автоматический сброс привязанного Telegram-аккаунта не реализован. Изменять БД вручную для обычного использования не требуется.

При первом открытии ссылки обзор истории ограничен, чтобы не засорять чат; это не копия всей переписки в Telegram. Полный контекст продолжает храниться у Дамира. Одноразовая ссылка не служит постоянной закладкой: закрепляй сам чат.

## Отдельный режим для нескольких пользователей

Прежний административный режим сохранён как `damir telegram-isolated`: каждому разрешённому ID назначается отдельный backend и Docker-том, без файлов консоли владельца. Его настройка описана в [TELEGRAM_ISOLATED.md](TELEGRAM_ISOLATED.md). Для персонального продолжения текущего разговора используй `damir telegram` или обычный `damir` и `/tg`.

## Проверки

`tests/BackendTests/CompanionChecks.cs` проверяет привязку, возврат по кнопке,
доставку и восстановление. `WorkspaceHandoffChecks.cs` воспроизводит A → B → A,
старый чат и старые ссылки. `TelegramMenuChecks.cs` проверяет меню через настоящий
Core и синтетический шлюз. Платные LLM и настоящий Telegram в этих тестах не вызываются.
