# Локальный пробный запуск

Это демонстрационный запуск: Core и файловые инструменты работают внутри
контейнера, а вызовы моделей идут через отдельный LiteLLM Proxy к OpenAI.
История, пересказы и счётчики одного демо-диалога хранятся в локальном PostgreSQL.
Долговременные факты хранятся отдельно в PostgreSQL/pgvector, эмбеддинги
вычисляет локальная Ollama через LiteLLM. Очередь, политики бюджетов и
полноценная наблюдаемость отсутствуют в прямом демо-примере. Обычный `damir`
использует HTTP CLI и очередь, см. [CLI.md](CLI.md).

## Долговременная память

При запуске `damir` поднимаются дополнительные сервисы `memory-db` и `embeddings`.
Первый запуск загружает `embeddinggemma:300m` (около 622 МБ) в Docker-том
`damir_embeddings`. Впоследствии launcher проверяет наличие модели и не обновляет
её автоматически. Ollama ограничена двумя CPU и 2 ГБ памяти; GPU не требуется.
Порты сервисов на хост не публикуются. Наружу Ollama подключается для загрузки
модели; запросы эмбеддингов остаются локальными. Поиск и генерация эмбеддингов
не расходуют платный API OpenAI. Отобранные факты передаются основной LLM
вместе с контекстом, как и обычные сообщения.

Примеры сообщений:

- «Запомни под ключом preferred-drink: я предпочитаю зелёный чай без сахара».
- В новой сессии той же папки: «Какой чай я предпочитаю?».
- «Обнови preferred-drink: теперь предпочитаю чёрный чай».
- «Покажи сохранённые факты и их ключи».
- «Забудь запись preferred-drink».

Сохранение зависит от вызова инструмента моделью. При ошибке инструмент не
подтверждает успех. Модель получает правило сохранять сведения по просьбе
пользователя, не делать выводы о нём из произвольных файлов и не сохранять секреты.
Это инструкции модели, а не гарантированный классификатор чувствительных данных.
При недоступности семантического поиска обычный разговор остаётся доступен;
модель получает указание не придумывать воспоминания. При недоступности самой
БД во время запуска консоль сообщает ошибку.

Настройки передаются через окружение:

```text
DAMIR_MEMORY_ENABLED=1
DAMIR_MEMORY_OWNER=local
DAMIR_MEMORY_PROJECT=<launcher вычисляет хеш пути workspace>
DAMIR_EMBEDDING_DEPLOYMENT=damir-memory-embedding
DAMIR_EMBEDDING_MODEL=ollama/embeddinggemma:300m
DAMIR_EMBEDDING_DIMENSIONS=768
```

Для временного отключения передай `DAMIR_MEMORY_ENABLED=0`. Данные при этом
не удаляются. Для разных локальных профилей задай разные DAMIR_MEMORY_OWNER.
Не задавай одинаковый DAMIR_MEMORY_PROJECT разным папкам, если не хочешь
намеренно объединить их память. Перенос папки меняет автоматически вычисленный
project_id. При ручном запуске через Compose идентификатор проекта необходимо
передать явно, а модель заранее загрузить командой
`docker compose exec -T embeddings ollama pull embeddinggemma:300m`.

Том `damir_memory` хранит записи и векторы отдельно от существующего
`damir_postgres` с историей. Образ старой БД не меняется; миграция её данных
не требуется. Пароль локальной памяти совпадает с локальным паролем демо-БД.
Резервировать нужно оба тома и файл пароля. Удаление записи памяти не удаляет
её упоминания из старой истории или резервных копий.

При смене модели либо размерности эмбеддингов нужно согласованно обновить
настройки LiteLLM и DAMIR_EMBEDDING_MODEL/DAMIR_EMBEDDING_DIMENSIONS, затем
заново сохранить записи с теми же ключами. Модель с прежним идентификатором
нельзя незаметно подменять другой версией: координаты векторов станут несовместимы.

Проверки без Docker: `dotnet run --project tests/MemoryTests/MemoryTests.csproj`.
Для интеграционных проверок укажи DAMIR_MEMORY_TEST_DATABASE_URL на отдельную
тестовую PostgreSQL с pgvector. Они используют случайный scope и удаляют свои
записи в finally. Для дополнительного теста настоящих эмбеддингов укажи
DAMIR_MEMORY_TEST_EMBEDDING_URL (LiteLLM) и DAMIR_MEMORY_TEST_EMBEDDING_KEY.
Ответная LLM в этом тесте заменена тестовым адаптером; платные генерации не вызываются.
Готовый скрипт с временной тестовой БД:
`pwsh -NoProfile -File tests/MemoryTests/run-integration.ps1`.
Добавь `-WithEmbeddings`, чтобы также проверить настоящие Ollama и LiteLLM.
Скрипт требует Docker и .NET SDK 10, использует случайные имена контейнеров и
тестовые пароли, удаляет свои контейнеры и сеть после проверки. Кэш модели
остаётся в томе проекта для повторного использования. Образы загружаются
последовательно; официальный образ Ollama занимает несколько гигабайт.
Все автономные .NET-проверки можно запустить на Linux через
`docker build -f docker/Dockerfile.tests -t personal-ai-agent-tests .`.

## Вход и запуск

Нужны Docker Desktop с Docker Compose и доступ к OpenAI. Запусти `./damir login`:
LiteLLM покажет ссылку и код, который нужно ввести на странице OpenAI. В настройках
безопасности аккаунта должен быть разрешён вход по коду устройства. Вход хранится
в отдельном Docker-томе `damir_auth`; токены обновляет LiteLLM. Существующие
учётные данные Codex не используются. Повторная команда использует текущую сессию.

После входа запусти `./damir` (или `./damir run`). Команда запускает шлюз и консоль агента;
при запуске консоль показывает большой рисунок Дамира с его именем, а в узком
терминале — компактную версию.
`/help` показывает команды, `/models` — настроенные модели, `/tokens` — расход токенов диалога,
`/context` — оценка текущего контекста, `/compress` вручную сжимает
историю, `/skill` показывает список навыков и позволяет выбрать навык для
следующего сообщения, `/skill имя` выбирает его по имени, `/exit` завершает
консоль. Выбор отменяется командой `/skill 0`. Доступность моделей
зависит от аккаунта. Ключ между агентом и шлюзом создаётся локально в
игнорируемом `.uv-cache/`; API-ключ OpenAI не нужен. Доступ к папке проекта,
Docker и Docker-томам следует ограничить владельцем компьютера.
В меню моделей `0` (или `/exit`) возвращает в чат без смены модели. Список
берётся из `config/litellm.yaml`, а не из каталога конкретного аккаунта: модель
может отображаться в списке, но быть недоступной для подписки. Текущая модель
отображается отдельно и отмечается в списке.
Неизвестные команды, начинающиеся с `/`, не передаются модели.

Многострочную вставку поддерживаем через bracketed paste в совместимых терминалах:
весь вставленный текст отправляется одним сообщением. Если терминал не поддерживает
эту возможность, введи `/multi`, вставь текст и набери `/send` отдельной строкой.
`/cancel` отменяет ввод; чтобы включить буквальную строку `/send` или `/cancel` в
текст, набери её с обратной косой чертой: `\/send` или `\/cancel`. Вставленный
текст не интерпретируется как команда Дамира.

Во время ответа в интерактивном терминале показывается временная строка состояния:
подготовка контекста, обращение к модели и имена вызываемых инструментов. Перед
ответом она очищается; аргументы инструментов и внутренние рассуждения модели не
отображаются. При перенаправлении вывода строка состояния отключается.

### Интернет-поиск

Дамир может вызвать `web.search`, чтобы найти актуальные сведения и ссылки.
Инструмент использует RSS-выдачу Bing без отдельного API-ключа: запрос
передаётся этому внешнему сервису. Выдача содержит заголовки, адреса и фрагменты,
а не полный текст страниц. Доступность, свежесть и релевантность результатов не
гарантированы; при блокировке, таймауте или ошибке инструмент сообщает о сбое.
Модели предлагается начинать с короткого запроса, близкого к словам пользователя,
и пробовать другую формулировку при нерелевантных результатах; решение о запросе
остаётся за моделью. Данные поисковых фрагментов могут быть устаревшими.
Страницы автоматически не открываются. Поиск выполняется в отдельном сетевом
контейнере без workspace и ключей шлюза; shell-песочница остаётся без сети.

### GitHub MCP

Для доступа к GitHub создай fine-grained personal access token с доступом только
к нужным репозиториям и правами чтения нужных разделов (например, Contents,
Issues и Pull requests). В диалоге введи `/github-login` (или `damir github-login`)
и вставь токен в появившееся скрытое поле терминала. Это ввод токена, а не вход
через браузер. Токен не попадает в историю чата. Консоль автоматически
перезапускается, история диалога сохраняется; выбранную в меню модель и навык
для следующего сообщения потребуется выбрать заново.

На macOS токен сохраняется в Связке ключей через `git credential-osxkeychain`,
на Windows — в Credential Manager через Git Credential Manager (должен быть
установлен с Git). На следующем запуске он загружается автоматически. Команда
`/github-logout` (или `damir github-logout`) удаляет запись Дамира и отключает
сервер; существующие учётные данные Git не затрагиваются. Отзыв токена на самом
GitHub не выполняется. Если токен отдельно задан в переменной окружения
`DAMIR_GITHUB_TOKEN`, её также нужно удалить вручную. Linux-хранилище пока не
подключено; на Linux по-прежнему можно задать эту переменную вручную.

Токен сохраняется без проверки GitHub: при неверном или отозванном токене
обращение к инструментам GitHub вернёт ошибку. Сервер работает в отдельном
контейнере с сетью, не видит workspace, shell-песочницу и ключ шлюза. Его
инструменты принудительно ограничены режимом чтения; токен передаётся только в
контейнер GitHub MCP и может быть виден локальному администратору Docker. Данные,
прочитанные из GitHub по запросу пользователя, попадают в диалог и в запросы к
модели. Проверка прав и реальный запрос требуют действительного токена. При
изменении состава инструментов нужно перезапустить Дамира.

Инструкции для всего проекта можно хранить в `.agents/AGENTS.md`; обычные
`AGENTS.md` в корне и вложенных каталогах тоже поддерживаются. Корневой файл
идёт после `.agents/AGENTS.md`, вложенные — после обоих и имеют приоритет для
своего каталога.

Навыки ищутся в `.agents/skills/<имя>/SKILL.md` выбранной папки проекта и в
старом расположении `skills/<имя>/SKILL.md`. При совпадении имён используется
навык из `.agents/skills/`. Модель может
сама выбрать подходящий навык по описанию или по просьбе пользователя. Команда
`/skill` показывает список с номерами и `0` для возврата; `/skill имя` выбирает
навык по имени. При успешной загрузке навыка для текущего хода консоль показывает
его имя, как при ручном выборе, так и при вызове моделью. Выбор действует для
одного следующего хода; команда проверяет
наличие и формат файла, но выполнение инструкций по-прежнему зависит от модели.
Пример навыка для ручной проверки находится в `examples/skills/citrus-oracle/`.

Для команды `damir` из любой папки на macOS/Linux один раз установи ссылку:

```sh
./install-damir
```

Скрипт создаёт ссылку в `~/.local/bin`, не перезаписывая существующий файл. Если
этой папки нет в PATH, добавь её в настройки своей оболочки. Затем перейди в папку
проекта и запусти агента:

```sh
cd "/путь/к/Todo List"
damir
```

Текущий каталог подключается в оба контейнера как `/workspace` с правом записи.
Дамир может читать и изменять файлы в нём и читать `AGENTS.md`; выбирай каталог
осознанно. По умолчанию каждой папке соответствует своя история: идентификатор
зависит от её полного пути, поэтому после переименования или переноса будет создана
новая история. При запуске из каталога Personal-AI-Agent сохраняется прежнее
поведение: используется его `workspace` и прежний локальный диалог. При явно
заданном `DAMIR_SESSION_ID` используется указанный идентификатор. Если переместить
сам репозиторий Дамира, ссылку потребуется установить заново.

На Windows можно добавить каталог Personal-AI-Agent в пользовательский PATH, затем
перейти в проект и запустить `damir`. Для временного PATH в PowerShell из каталога
Personal-AI-Agent выполни `$env:PATH += ";$PWD"`. Для работы требуется PowerShell 7;
при вызове `damir` из Windows PowerShell 5.1 вход через `damir.cmd` запускает
локальный `.dotnet/tools/pwsh.exe` или установленный PowerShell 7.
Проверка на реальной Windows пока необходима.

Консоль передаёт модели системный промпт с характером Дамира: уверенный,
язвительный помощник, который остаётся полезным и бережным в серьёзных ситуациях.
Промпт добавляется в каждый запрос к модели и не записывается в историю диалога.
Вместе с ним передаются дата, время и часовой пояс на начало хода. Они сохраняются
неизменными при вызовах инструментов в рамках одного хода.
Команда `damir` пытается определить часовой пояс компьютера; если это не удалось,
она сообщает о переходе на UTC. Пояс можно задать явно, например:
`DAMIR_TIMEZONE=Asia/Tomsk ./damir run`. Указывается имя часового пояса из базы
IANA. Время может устареть во время выполнения хода и обновится при следующем.

Перед каждым запросом LiteLLM оценивает число входных токенов выбранной модели,
включая инструменты; ядро добавляет запас к оценке. Эта оценка не равна точному
подсчёту провайдера. Для шести настроенных моделей используются справочные окна
из локального каталога Codex на 21.11.2026: 500 000 токенов для gpt-6.2-sol,
gpt-6.1-sol и gpt-6.1-terra; 272 000 — для gpt-6.2-astra, gpt-6-astra и
gpt-6-luna. Это снимок настроек Codex, а не подтверждённый лимит доступа через
LiteLLM и ChatGPT; он не обновляется автоматически и может устареть. Для
неизвестной модели используется 30 000. При смене модели окно выбирается заново.
Бюджет подготовки запроса по умолчанию — 95% справочного окна, но не больше
max_input_tokens, если шлюз вернул меньшее значение. Ядро дополнительно
увеличивает оценку токенов на 15% и 128 токенов для запаса, поэтому автоматическое
сжатие может начаться заметно раньше 100% окна. `DAMIR_CONTEXT_TOKENS=40000
./damir run` позволяет задать меньший рабочий бюджет (минимум 4096); верхнее
ограничение справочным окном и лимитом шлюза сохраняется. Данные шлюза могут
относиться к API и отличаться от лимитов подписки ChatGPT, поэтому гарантий
помещения в окно модели нет. Генерация использует Responses API через шлюз;
выходные элементы, включая служебные элементы reasoning при их наличии,
сохраняются в истории диалога и передаются обратно той же модели. Старые диалоги
без них остаются совместимыми с новой версией. Старые версии приложения не смогут
прочитать новые записи с этим полем без миграции.
Время обновляется между ходами, а сжатие меняет историю: при изменении префикса
провайдер может не использовать ранее переданное reasoning-состояние.
Счётчик шлюза работает с форматом сообщений; адаптер включает в оценку
зашифрованные reasoning-элементы как текст. Оценка может отличаться от реального
числа токенов, занятых состоянием модели.

При превышении бюджета старые ходы пересказываются через шлюз; особо длинные ходы
обрабатываются частями. Системные и проектные инструкции и текущий ход остаются
целыми. `/compress` включает использование пересказа вручную и для следующих
запросов, даже если автоматический порог ещё не достигнут. Пересказы кешируются
в PostgreSQL по содержимому и повторно используются при совпадении. Исходная
история не удаляется. Если пересказ не уменьшил оценку контекста, `/compress`
сообщит об этом. Суммаризация расходует дополнительные запросы и может
упускать детали; если текущий ход слишком велик или пересказ не удался, агент
вернёт ошибку. При отсутствии счётчика подсистема Core использует байтовую оценку;
демонстрационная консоль требует работающий счётчик шлюза.

Команда `/tokens` показывает суммарное число токенов диалога по данным шлюза,
включая предыдущие запуски, входные и выходные токены. В сумму
входят также запросы на сжатие. Если шлюз не вернул полные сведения, консоль
выводит знак ≥: итог тогда может быть неполным. Это не счётчик
использования всей подписки. Команда `/context` запрашивает оценку сохранённого
контекста, включая системные и проектные инструкции и схемы инструментов; текст
следующего сообщения в неё не входит. Если готовый пересказ подходит, он учитывается
вместо старой истории; новые сообщения добавляются к нему. Команда не вызывает
генерацию нового пересказа и сообщает об ошибке, если оценить контекст не удалось.
Вывод `~токены / окно (процент%)` показывает оценку к справочному окну Codex
либо к меньшему лимиту ввода шлюза; для неизвестной модели — к рабочему
резервному значению. Это не подтверждение фактического лимита подписки.
Ручной рабочий бюджет может быть меньше показанного окна.

PostgreSQL запускается в отдельном контейнере без публикации порта на хост.
Данные диалога, включая запросы, ответы и результаты инструментов, хранятся в
локальном Docker-томе `damir_postgres` до его удаления. Пароль базы создаётся в
игнорируемом `.uv-cache/damir-db-password`: сохраните его вместе с томом для
восстановления. Историю и пересказы хранит общий `PostgresContextStore` в модуле
Memory; демонстрационная консоль подключает его через адаптер. Прямой пример
блокирует одновременное открытие одной сессии двумя экземплярами. Обычный
`damir` теперь запускает HTTP CLI и backend с очередью; весь ход сессии
сериализует Worker. `damir backend` запускает HTTP отдельно. Устройство и
ограничения описаны в [BACKEND.md](BACKEND.md) и [CLI.md](CLI.md).
Telegram запускает отдельную пару backend/shell для каждого разрешённого ID
с собственными workspace и IPC-томами, без подключения файлов хоста или общего
GitHub-токена. Подробности в [TELEGRAM.md](TELEGRAM.md).
Примеры прямого Compose-сервиса `agent` в этом
документе сохранены для проверки Core.

## Границы и ограничения

Агент работает под непривилегированным пользователем, с read-only корнем,
временным `/tmp`, без Linux capabilities, с ограничением памяти, CPU и процессов.
Он подключён к внутренней сети с Proxy и PostgreSQL; наружу выходит Proxy.
Docker socket агенту не передаётся. Монтируется предназначенный для тестов
workspace с правом записи. Это контейнерная граница для данного примера, а не
доказательство полной безопасности Docker или защита от всех уязвимостей хоста и
контейнерного движка.
Проверки путей в инструментах отдельно не гарантируют защиту от гонок и жёстких
ссылок.

Инструмент `shell.execute` выполняет команды без подтверждения в отдельном
контейнере `shell-sandbox`, с которым агент общается через Unix-сокет. Для каждого
запуска агента создаются собственные контейнер команд и том сокета; они удаляются
после завершения сеанса. Это позволяет одновременно работать с разными папками.
Контейнер не подключён к сети, не имеет Docker socket или ключей шлюза и базы.
Рабочий каталог — общий `/workspace`, файлы которого команды могут менять и
удалять. Корневая файловая система доступна только для чтения; процессы, память и
CPU ограничены. Контейнер не перезапускается после команд: фоновые процессы и
файлы в `/tmp` могут сохраняться между вызовами до остановки контейнера.
При таймауте или отмене выполняющийся процесс и его дерево останавливаются, но
уже отделившиеся процессы могут продолжать работать. На команду выделено 30 секунд
по умолчанию (от 1 до 120); stdout и stderr ограничены 16 384 символами каждый.

Сейчас поддерживаются `/bin/sh` и PowerShell 7 (`pwsh -NoLogo -NoProfile -Command`)
внутри Linux-контейнера на хостах с Docker. Это Linux-версия PowerShell, а не
нативная оболочка Windows или macOS: доступ к ОС хоста не предоставляется.
Нативные средства Windows и macOS требуют отдельной реализации и проверки.
Контейнер не является абсолютной защитой от уязвимостей контейнерного движка; workspace остаётся доступен для записи.

### Запуск на Windows

Для запуска подготовлены `damir.cmd` и внутренний `damir-launcher.ps1`: требуются PowerShell 7+
(`pwsh`) и Docker Desktop в режиме Linux-контейнеров. Из папки проекта:

```powershell
.\damir.cmd login
.\damir.cmd run
```

Эквивалентно можно вызвать `pwsh -NoProfile -File .\damir-launcher.ps1 login` и затем
`pwsh -NoProfile -File .\damir-launcher.ps1 run`. Скрипт создаёт локальные ключи в
игнорируемой папке `.uv-cache`. Для PowerShell 7.0–7.1 автоматическое
преобразование часового пояса Windows в IANA может быть недоступно: скрипт
предупредит и выберет UTC; нужный пояс можно передать в `DAMIR_TIMEZONE`.

Проверка PowerShell-скрипта без реального Docker и без входа в аккаунт:
`pwsh -NoProfile -File .\tests\windows-launcher-check.ps1`. Реальный запуск
Windows и запись файлов через Docker Desktop необходимо проверить на машине с
Windows; подготовленные скрипты пока не являются подтверждением такой проверки.
Для такой проверки сначала убедитесь, что `docker info --format '{{.OSType}}'`
выводит `linux`, затем выполните проверку скрипта, `login` и `run`. В диалоге
попросите Дамира выполнить `uname -s` и `pwsh -Version`;
ожидаются `Linux` и версия PowerShell 7 или выше. Также попросите создать и
прочитать новый тестовый файл в `workspace` и проверьте его на Windows-хосте.
Коды входа и токены в чат или журнал проверки передавать не нужно.

Образ LiteLLM зафиксирован по digest проверенной локальной версии; обновления
образа и проверка его совместимости выполняются отдельно. Proxy в этом примере не
публикует порт на хост, а его конфигурация не включает базу учёта расходов,
бюджеты или телеметрию. Тесты адаптера используют поддельные HTTP-ответы;
успешная сборка не подтверждает доступность OpenAI или корректность ключа.

расходов и бюджеты для подписки в этом примере не настроены.
