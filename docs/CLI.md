# CLI через общий backend

`damir` и `damir run` теперь запускают HTTP-клиент из
`src/ai_agent/interfaces/cli/`. Сообщения проходят через API → PostgreSQL/Redis →
Worker → Core. CLI не обращается к БД, шлюзу или инструментам, не хранит
собственную историю и не запускает Agent Loop. `shared/` не меняется.

## Запуск и сессии

После `damir login` выполни `damir` из папки проекта. Launcher поднимает
зависимости, собственные backend, песочницу и при необходимости GitHub MCP,
затем консоль. Порт этого backend на хост не публикуется. При выходе
останавливаются собственные контейнеры и удаляются их IPC-тома; базы остаются.
Для одной пары owner/project по-прежнему допускается один Worker.

`DAMIR_SESSION_ID` задаёт **имя диалога**. Backend сопоставляет имя с серверным
ID внутри owner/project. По умолчанию launcher использует `local` для
`workspace` или имя на основе пути проекта. Повторный запуск открывает ту же
API-сессию; разные проекты изолированы. Старая история демонстрационной
консоли остаётся в БД, но автоматически не присваивается API-сессии.

`/session` показывает ID, `/session ID` открывает API-сессию этого проекта,
`/new` создаёт отдельную сессию. Новый ID нужно сохранить: `/new` не меняет
диалог по умолчанию. При старте видна последняя сохранённая задача;
`/task ID` получает её результат после разрыва связи или перезапуска.

## Команды

| Команда | Действие |
| --- | --- |
| `/models` | Выбрать модель для последующих задач |
| `/skill`, `/skill имя`, `/skill 0` | Каталог, выбор навыка на следующее сообщение, отмена |
| `/tokens` | Сохранённый расход; `≥` означает неполные данные usage |
| `/context`, `/compress` | Оценка и ручное сжатие через Core в очереди сессии |
| `/multi` | Многострочный ввод: `/send` отправляет, `/cancel` отменяет ввод |
| `/session [ID]`, `/new` | Работа с сессиями backend |
| `/task ID`, `/cancel ID` | Результат или запрос отмены задачи |
| `/retry` | Повторить неясную отправку с исходным запросом и ключом |
| `/discard` | Забыть ключ неясной отправки; принятую задачу не отменяет |
| `/github-login`, `/github-logout` | Вернуться в launcher для изменения хранилища GitHub |
| `/exit` | Выход |

Модель и навык сохраняются у задачи. Навык проверяется сервером перед
постановкой и читается Core при выполнении; его имя не добавляется к тексту
сообщения. Эмбеддинг-модель исключена из chat-каталога. `/context` и `/compress`
имеют `task_id`, идут по порядку с сообщениями, поддерживают отмену и не
записываются в историю LLM. Счётчики включают пересказы. Контекст остаётся
оценкой; слишком короткая история может не сжиматься, возвращая ошибку Core.

Во время ожидания Ctrl+C запрашивает отмену задачи и возвращает ввод.
Отмена кооперативная: `/task ID` проверяет конечный статус. На приглашении
ввода Ctrl+C завершает CLI. События отдельных инструментов по HTTP пока
не передаются; консоль показывает ID задачи и ждёт результат.

## Потерянный ответ

Каждая отправка получает `Idempotency-Key`. `/retry` передаёт тот же текст,
модель, навык и операцию с прежним ключом. Backend возвращает ту же задачу,
включая завершённую; изменение запроса с тем же ключом даёт 409.
Восстановление квитанции не требует доступности модели или файла навыка.
Если каталог моделей недоступен при старте, CLI позволяет проверить задачи;
для новой отправки сначала восстанови каталог командой `/models`.
До `/retry` или явного `/discard` новая отправка блокируется. Ошибка чтения
статуса не вызывает повторной отправки.

Неясный запрос хранится только до закрытия CLI; при выходе выводятся ID
сессии и ключ. После перезапуска проверь последнюю задачу перед повторной
отправкой. Постоянное хранилище незавершённых отправок пока не реализовано.

## Отдельный backend

`damir backend` публикует HTTP на loopback. Подключение второй консоли
из репозитория с установленным .NET SDK 10, в PowerShell:

```powershell
$env:DAMIR_BACKEND_URL = 'http://127.0.0.1:8080'
$env:DAMIR_BACKEND_API_KEY = (Get-Content -Raw .uv-cache/damir-backend-key).Trim()
$env:DAMIR_SESSION_ID = 'local'
dotnet run --project src/ai_agent/interfaces/cli/Cli.csproj
```

Backend обслуживает один workspace; клиент не выбирает путь или scope.
Команды GitHub вне штатного launcher возвращают коды 71/72; отдельно
запущенный backend после изменения токена требуется перезапустить.

`examples/SandboxConsole` и сервис Compose `agent` сохранены для прямых
проверок Core. Обычный launcher их не вызывает. Telegram использует те же
маршруты в отдельных backend для каждого ID. Данные CLI и Telegram разделены;
подробности в [TELEGRAM.md](TELEGRAM.md).

## Проверки

`dotnet run --project tests/CliTests/CliTests.csproj` проверяет транспорт.
`pwsh -NoProfile -File tests/BackendTests/run-integration.ps1` проверяет
процесс CLI, API, Redis, PostgreSQL, Worker и Core с синтетическими ответами
LLM, без платных вызовов. Проверки launcher:
`tests/windows-launcher-check.ps1`, `tests/LaunchTests/memory-workspace.sh`,
`tests/LaunchTests/github-auth.sh`.
