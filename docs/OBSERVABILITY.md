# Наблюдаемость Дамира

Обычные CLI и Telegram используют backend с JSON-логами задач. При включении
наблюдаемости backend отправляет OpenTelemetry-трассы и метрики по OTLP/HTTP
protobuf. Возможны локальный Collector, свой OTLP-приёмник и Langfuse.
По умолчанию экспорт выключен.

## Что записывается

- HTTP-метод, шаблон маршрута и код ответа. Путь с конкретным ID, query,
  заголовки, IP и тело запроса не записываются.
- Выполнение задачи: task_id, статус и длительность. Сессия представлена
  SHA-256 от owner/project/session, исходные Telegram ID и имена не отправляются.
  Это псевдонимизация для корреляции, не гарантия анонимности.
- Вызовы модели: имя модели, длительность и фактические входные/выходные токены,
  если шлюз их вернул. Неизвестный расход не заменяется выдуманным значением.
- Инструменты: длительность, результат и имя известного встроенного инструмента.
  Для неизвестных имён используются категории `custom`, `mcp` или `unknown`.

Сообщения, ответы модели, содержимое файлов, команды shell, аргументы и результаты
инструментов, исключения с текстом провайдера и секреты не включаются в трассы.
`tracestate` удаляется перед экспортом. Автоматическая инструментация HTTP-клиента,
SQL и захват тела запросов не включены. JSON-логи Worker содержат идентификаторы
задачи/сессии и, при наличии, TraceId и SpanId. Тексты диалогов в них не пишутся.

## Сквозная трасса

```text
http.request POST /tasks
  └─ task.execute (Worker)
       └─ agent.run (Core)
            ├─ llm.complete
            ├─ tool.execute
            └─ llm.complete
```

При принятии новой задачи текущий W3C `traceparent` сохраняется в nullable-столбце
`damir_api_tasks.traceparent`. Worker читает его с проверкой owner/project.
Связь сохраняется после очереди и перезапуска backend. Повтор с прежним
Idempotency-Key сохраняет исходный контекст; старым задачам без traceparent
назначается новая трасса при выполнении. Тела HTTP DTO и контракты shared
не менялись. Контекст tracing не используется как авторизация.

Типы Langfuse: `agent`, `generation` и `tool`. Task ID, псевдоним сессии и имя
трассы передаются дочерним spans без помещения пользовательских данных в baggage.
Запросы проверки статуса — отдельные HTTP-spans; исходная задача связывается
с запросом приёма, а не с каждым последующим polling-запросом.

## Локальная проверка

Windows, PowerShell из папки репозитория:

```powershell
$env:DAMIR_OBSERVABILITY_ENABLED = '1'
$env:DAMIR_OTEL_ENDPOINT = 'http://otel-collector:4318'
.\damir.cmd telegram
```

macOS, Terminal из папки репозитория:

```sh
export DAMIR_OBSERVABILITY_ENABLED=1
export DAMIR_OTEL_ENDPOINT=http://otel-collector:4318
./damir telegram
```

Вместо `telegram` можно использовать обычный запуск CLI или `backend`.
Launcher автоматически поднимет Collector, если включён экспорт и в окружении
задан именно `http://otel-collector:4318` (допустим завершающий `/`).
После тестового сообщения метаданные трассы доступны через Docker Desktop
в логах сервиса `otel-collector`. Метрики отправляются периодически, обычно
раз в 60 секунд. Collector доступен только в Docker-сети, порты хоста не открыты.
Он выводит данные в свои логи и не является постоянным хранилищем или веб-интерфейсом.

Профиль `observability` не запускается при обычной работе без настройки экспорта.
Collector остаётся общей инфраструктурой после остановки CLI/бота, как PostgreSQL
и шлюз. Для выключения экспорта задай `DAMIR_OBSERVABILITY_ENABLED=0` и перезапусти
backend. Свой Collector можно подключить через другой базовый OTLP URL;
launcher такой сервис не запускает.

## Langfuse

Потребуется проект в существующем Langfuse Cloud либо собственном Langfuse.
Развёртывание сервера Langfuse не входит в этот этап. Отдельный Collector для
отправки в Langfuse не требуется.

В окружении процесса, запускающего Дамира, задай:

| Переменная | Значение |
| --- | --- |
| `DAMIR_OBSERVABILITY_ENABLED` | `1` |
| `DAMIR_LANGFUSE_ENDPOINT` | Базовый URL, например `https://cloud.langfuse.com/api/public/otel` |
| `LANGFUSE_PUBLIC_KEY` | Public key проекта Langfuse |
| `LANGFUSE_SECRET_KEY` | Secret key проекта Langfuse |
| `DAMIR_OTEL_ENDPOINT` | Пусто для одного Langfuse; адрес своего Collector для параллельного экспорта |

В PowerShell 7 секрет можно задать без записи значения в историю команды:

```powershell
$env:LANGFUSE_SECRET_KEY = Read-Host 'Secret key проекта Langfuse' -MaskInput
```

Сохраняй ключи локально, вне Git. `.env.example` содержит только пустые образцы;
сама C#-программа `.env` не загружает. Для описанного автоматического старта
локального Collector настройки должны быть переменными окружения launcher.

Экспортёр добавляет `/v1/traces` к базовому Langfuse URL и использует Basic Auth
с ключами проекта и `x-langfuse-ingestion-version: 4`. Ключи отправляются только
экспортёру Langfuse; generic Collector их не получает, HTTP-redirect запрещён.
Endpoint не должен содержать credentials, query или fragment.
Схема соответствует [официальной OTLP-интеграции Langfuse](https://langfuse.com/integrations/native/opentelemetry).

## Настройки и ограничения

`DAMIR_TRACE_SAMPLE_RATIO` — число от 0 до 1, по умолчанию 1. Применяется
parent-based sampling; решение уже известного родителя сохраняется.
Значение 0 отключает запись новых корневых трасс, но не метрики.
Метрики имеют ограниченный набор меток, task/session ID в метки не попадают.

Экспорт выполняется в фоне с очередью до 1024 spans, пакетами до 128,
интервалом около секунды и таймаутом запроса 3 секунды. При недоступном приёмнике
задача продолжает выполняться; телеметрия может теряться. Она не является
журналом аудита или основанием для повтора инструмента.

Измеряются `damir.task.completed`, `damir.task.duration`, `damir.llm.tokens`,
`damir.llm.duration`, `damir.tool.completed` и `damir.tool.duration`.
Денежные бюджеты и их принудительное соблюдение ещё не реализованы.
Оценка стоимости в Langfuse зависит от его каталога моделей; это не фактический
счёт провайдера. Отдельная трассировка эмбеддингов и прямая демонстрационная
консоль `examples/SandboxConsole` пока не инструментированы этим этапом.

## Проверки

- `dotnet run --project tests/ObservabilityTests/ObservabilityTests.csproj`:
  настоящая передача OTLP на локальный HTTP-сервер, схема Langfuse с синтетическими
  ключами, метрики, скрытие содержимого, ошибки/отмена, отказ и redirect экспортёра.
- `pwsh -NoProfile -File tests/BackendTests/run-integration.ps1`:
  настоящий PostgreSQL/Redis, сохранение контекста при приёме, продолжение после
  перезапуска, идемпотентность, изоляция и совместимость остального backend.
- `docker build -f docker/Dockerfile.tests -t personal-ai-agent-tests .`:
  общий автономный набор, включая тесты наблюдаемости и Unix launcher.

Живой проект Langfuse и настоящая модель в этих проверках не используются.
После настройки своего Langfuse нужно вручную проверить появление одной трассы
с дочерними вызовами модели и инструмента.
